Data for finance: databases, SQL, DSA, KDB+/Q

How to efficiently store, query and structure financial data, including at high frequency.

Algorithmic complexity O(1) direct access  <  O(log n) sorted search  <  O(n) simple scan  <  O(n²) pairwise comparison

Relational databases

  • Organize data into tables linked by keys (primary/foreign key).
  • Guarantee data integrity through constraints.
  • The standard for transactional data (positions, orders, counterparties).

SQL

  • Universal language for querying and manipulating relational databases.
  • SELECT / JOIN / GROUP BY: the 3 building blocks to master first.
  • A skill expected almost everywhere in quantitative finance.

DSA (data structures)

  • Lists, trees, hashmaps, queues: the choice of structure directly impacts performance.
  • An order book is often modeled with trees or sorted queues.
  • Essential for any low-latency trading system.

KDB+/Q

  • Columnar database specialized in very high-frequency time series.
  • Used by high-frequency trading desks to store and query tick data.
  • The Q language is notoriously hard but extremely fast for this use case.

Who uses what?

Data engineer Designs and maintains the organization's pipelines and databases.
Quant developer Uses DSA to optimize the performance of pricing/risk engines.
Analyst Queries data via SQL to produce analysis and reporting.
High-frequency trader Relies on KDB+/Q to analyze tick data in near real time.

Key takeaways

  1. SQL remains the single most universally useful data skill in finance, ahead of any specific programming language.
  2. The choice of data structure (DSA) becomes critical as soon as latency or data volume grows significantly.
  3. KDB+/Q only makes sense for very large volumes of tick-by-tick data — overkill for a monthly report.

Real-world examples

SQL query

Extract a security's 5-year price history with a simple SELECT ... WHERE ... ORDER BY date.

KDB table for tick data

Store millions of trades a day and compute a VWAP in milliseconds thanks to KDB+'s columnar storage.

Hashmap for lookups

Map an instrument ID to its attributes with instant O(1) access instead of scanning a list.

Tree for an order book

An order book is often implemented with a balanced tree to quickly find the best bid/ask price.

Quick glossary

Primary key Unique identifier of a row in a database table.
Index Structure that speeds up search within a database.
Q language Query language associated with KDB+, geared toward time-series processing.
Time-series database Database optimized for storing and querying time-stamped data.
Big-O Notation that measures an algorithm's complexity/performance as data size grows.
Order book Real-time record of buy and sell orders for an instrument.
